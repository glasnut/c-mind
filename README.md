# C-Mind

Умный помощник по выбору комплектующих: сравнение, анализ, подбор сборки.
Стек: React + Vite + React Router, чистый CSS, шрифт Manrope.

## Запуск

```bash
npm install
npm run dev      # режим разработки, http://localhost:5173
npm run build    # сборка в папку dist
npm run preview  # посмотреть собранную версию, http://localhost:4173
```

## Как устроен проект

- `src/pages/` — страницы (одна папка на страницу). Готовы все: главная, каталог, карточка товара, сравнение, анализатор, подбор ПК, личный кабинет и «О проекте».
- `src/components/` — повторно используемые части интерфейса: шапка, подвал, карточка товара, поиск, кнопки, бейдж оценки.
- `src/data/` — демо-база комплектующих (JS-файлы). Цены условные.
- `src/services/products/` — единая «точка доступа» к товарам. Страницы берут данные только через неё, поэтому позже JSON можно заменить на API или базу данных, не переписывая интерфейс.
- `src/services/scoring/` — расчёт оценок по характеристикам.
- `src/services/catalog/` — фильтры, поиск и сортировка каталога (`filters.js` — набор фильтров для каждой категории).
- `src/services/storage/` и `src/context/` — сохранение данных в браузере и состояние (избранное, сравнение, пользователь).
- `src/services/analysis/`, `assistant/`, `builder/`, `auth/` — анализ, консультант, конфигуратор, аккаунты (подробнее ниже).
- `src/styles/` — цвета и размеры (`tokens.css`), базовые стили (`base.css`).

## Важно знать

- Цены в демо-базе условные и не являются актуальными предложениями.
- Оценки рассчитываются автоматически по формулам, это не нейросеть.

## Анализатор и консультант

- `src/services/analysis/` — правила: плюсы/минусы, альтернативы, «когда невыгодно» (`full.js` собирает всё вместе).
- `src/services/assistant/` — консультант. Сейчас отвечает по правилам (режим `rules`), нейросеть не подключена.
- Подключение языковой модели позже: написать провайдер с методом `answer(question, context)`, возвращающим `{ text, mode: 'llm' }`, и создать ассистента через `createAssistant({ provider })`. Интерфейс менять не нужно.
- Сценарии и их веса — `src/data/scenarios.js`.

## Подбор ПК

- `src/services/builder/compatibility.js` — все проверки совместимости (сокет, тип и объём памяти, формат платы, длина видеокарты, высота кулера, мощность и формат блока питания, PCIe, M.2, встроенная графика). Каждая работает только по данным из базы; чего в базе нет (например, поддержка радиатора СЖО корпусом), то честно выводится как «проверьте по документации».
- `src/services/builder/index.js` — итоги: цена, потребление, оценка по цели сборки, подсказки по балансу.
- Текущая сборка и сохранённые сборки хранятся в `localStorage` (ключи `cmind:builder-draft`, `cmind:builds`).

## Личный кабинет и аккаунты

- `src/services/auth/` — регистрация, вход, выход, удаление аккаунта. Пароль хранится только как хеш (PBKDF2-SHA256, 210 000 повторов, случайная соль на пользователя), в открытом виде его нет нигде. После 5 неверных попыток вход блокируется на 30 секунд.
- Аккаунты хранятся в `localStorage` браузера: это демо без сервера, аккаунт существует только на этом устройстве. Блокировка попыток тоже клиентская и защищает только от случайного перебора. При подключении сервера `register/login/logout` заменяются запросами к API, интерфейс не меняется.
- `src/context/AuthContext.jsx` — текущий пользователь. Данные пользователя лежат под ключами `u.<id>.<имя>` (избранное, сравнение, сборки, сохранённые сравнения, история), поэтому аккаунты не смешиваются. При регистрации то, что гость уже собрал, копируется в аккаунт.
- История действий ведётся только у вошедших (последние 50 записей).
